# Google ドライブ接続方式の評価と決定

## 結論

**アプリ内で Drive API v3 を直接呼ぶ。認証はユーザー自身の Google Cloud プロジェクトの OAuth クライアント（デスクトップ アプリ種別、PKCE + ループバック）。** rclone はアプリからは使わず、開発時の読み取り専用の照合（フォルダ一覧と md5 の突き合わせ）にだけ使う。

## 比較

| 観点 | ネイティブ OAuth + Drive API（採用） | rclone（`gdrive:` などの既存リモート） |
|---|---|---|
| 本アプリの方針（Drive API を直接呼ぶ） | そのまま満たす | rclone を介した間接呼び出し。外部 CLI への依存が増える |
| 認証情報 | 自分のクライアント。トークンは macOS キーチェーンだけに置く | **rclone の共有 client_id は廃止予定と案内されている**（rclone 実行時の警告、および rclone の公式ドキュメント https://rclone.org/drive/#making-your-own-client-id ）。継続利用には結局、自分の client_id を作る必要がある |
| 初期の手間 | Google Cloud でクライアント作成（約 10〜15 分、本人の操作が必要） | 設定済みの場合は手間が少ない。ただし上記の廃止により再設定が必要になる見込み |
| 重複判定（md5Checksum 一覧） | `files.list` の `md5Checksum` を直接読む | `rclone lsjson --hash` で取得可（数千件規模のフォルダでも取得できた） |
| 大きいファイルへの耐性 | 再開可能アップロードを自前で実装（8 MiB チャンク、状態問い合わせ、バックオフ、404 時は最初から） | rclone も 8 MiB 超は再開可能アップロード（チャンクのリトライあり） |
| 上書きの危険 | 常に新規作成（`files.create`）。既存ファイルには触れない | `copyto` は同名の既存ファイルを**更新（上書き）**しうる。同名・別内容のファイルが既にあるフォルダでは内容を壊すおそれがある |
| アップロード後の照合 | API 応答と一覧の両方で md5 を確認 | `lsjson` で別途確認が必要 |
| トークンの置き場所 | キーチェーン（端末限定、アンロック後のみ） | `~/.config/rclone/rclone.conf` に平文 |
| 権限の範囲 | `drive`（Drive 全体の読み書き） | 同じく `drive`（既存設定） |

rclone の client_id 廃止によって、rclone 側の「認証済みで手間がかからない」という利点はほぼ消える。「上書きの危険」と「Drive API を直接呼ぶ方針との一致」もあるため、ネイティブを採用する。

## スコープ

- 重複判定には、**アプリが作っていない既存ファイル**の md5Checksum を一覧で読む必要がある。`drive.file`（アプリが開いた／作ったファイル単位の権限）では読めない見込みが高い（公式ドキュメントでは確認できず、権限はファイル単位と説明されている）。
- 公式ドキュメント上、確実に満たせるのは `https://www.googleapis.com/auth/drive`（制限付き）。`drive.readonly` + `drive.file` の組み合わせのほうが狭いが、フォルダへの新規作成が通るかはドキュメント上未確認。どちらも「制限付き」区分なので、審査・警告の扱いは変わらない。
- まず `drive` で動かす。将来狭めたい場合は `GoogleAuth.scopes` の定数 1 箇所を変え、実機で作成・一覧が通るかを確かめる。

## 公開ステータスとトークン寿命（公式ドキュメントより）

- 外部 + 「テスト中」: リフレッシュトークンは **7 日で失効**（developers.google.com/identity/protocols/oauth2）。
- 個人モード: 作成者のアカウント専用。審査・ユーザー上限・7 日失効の対象外（support.google.com/cloud/answer/15549945）。新規プロジェクト作成時にしか選べない。
- 外部 + 本番（未審査）: 「未確認のアプリ」画面が出るが、自分で続行できる。新規ユーザーは 100 人まで。
- デスクトップ アプリは「公開クライアント」で、client_secret は機密扱いではない（developers.google.com/identity/protocols/oauth2/native-app）。ただしトークン交換時には送る。
